Thirty-eight icons and a logo, drawn as lists of points

A small hand-drawn icon set and a ridgeline logo carry the navigation, the phone tab bar and every index row. This is how they are drawn, why the first version was thrown out, and the rules that keep new icons consistent.

By Nate AndersonNov. 21, 20265 min read3 sourcesLab 2 of 7

01What the icons are for

The site had text links and nothing else, and on a phone the bottom tab bar needs a symbol for every tab. I wanted a set that looks drawn rather than printed, small enough to ship as one file, and consistent enough that a new icon could be added by someone following the written rules.

The set covers three jobs. Navigation icons sit in the header, the search button and the phone tab bar. Interface icons are arrows, chevrons, a check, a warning and similar. Topic icons start each row of the Field Guide, notes and studies indexes: heat, tree, shade, pavement, water, river, soil, sidewalk, bioswale, permeable paving, leaf, thermometer, pin, ruler and building.

02How they are made

Each icon is a short list of points on a 24 by 24 grid, written by hand in scripts/build_icons.py. The script then roughens the points with a seeded wobble, so the output is stable from run to run, and writes the sprite, the logo, the favicon and a names file that the gallery reads. I never edit the sprite directly: I edit the point list and run the script.

A stroke can be a polyline with sharp corners, a smooth curve through points, a closed shape, or a circle. Any stroke can be marked as the accent, and any can lay a pale tint under it that is printed slightly off the line, like a marker that missed the edge. Linework uses currentColor, the accent uses one token, and the tint uses another, so a single CSS class recolors an icon (moss for trees, slate for water) without a second drawing.

The first version was more detailed. I replaced it the same day with a set of two or three strokes per icon, a bolder line and a three-stroke logo, because fine detail does not survive at the sizes used beside body text. That is my judgment from looking at the icons at 16, 24 and 32 pixels. The gallery below is the second version.

03The mark

The logo is two ridgelines forming a valley. The ink line is the valley as it was drawn. The brick line beneath it is the same ridge redrawn, and a small brick sun sits low in the gap. That is the site’s whole idea in three strokes: look at a place, then redraw it. It has to read at 16 pixels because that is the favicon size, so the three-stroke limit is not decoration.

In the header it sits left of the wordmark; the favicon is the same mark on a paper tile. Because both are made from the same point lists as the icons, they share the wobble.

04The decisions I made

Two or three strokes per icon, with one accent stroke on the meaningful part

The accent is how an icon gets personality without a second color system: the door of the house, the leading edge of the pencil. Anything that needs more strokes is an illustration, not an icon.

CostSome topics (bioswale, permeable paving) are abstract at this size and rely on the label next to them.

Never fill with solid ink

Solid fills turn into blobs when the line is wobbly and break the sketch feel. Pale tints are allowed because they sit off the line and read as paper and marker.

CostIcons look lighter than a standard UI set next to bold text.

Keep the source as point lists, not hand-edited SVG

A point list is readable, diffable and easy to restyle; I could make the whole set bolder in one edit, which is what the second version needed.

CostAdding an icon means editing a Python file, which is a barrier for a contributor who only knows SVG.

Linework follows the text color

Using currentColor means icons work on paper, on the dark footer and in the active tab with no extra assets.

CostA single accent color per icon; no two-accent icons.

Ship one sprite, referenced with use

One request, cached, and every icon can be restyled in CSS.

CostExternal sprite references need HTTP, so icons do not appear if you open a page from disk.

05The live gallery

Every icon, at its real size, grouped the way they are used. Click an icon to copy its markup. The sizes and tab-bar sections lower on the page show how they scale.

06What I could not verify

Limits of this lab

  • I judged legibility at 16, 24 and 32 pixels by eye on one screen. I did not test the icons with people, or on low-resolution displays.
  • The icons are decorative and hidden from screen readers; the text beside each one carries the meaning. I have not tested that with a screen reader.
  • The count of 38 is read from the generated names file on the day I wrote this and will change as icons are added.
