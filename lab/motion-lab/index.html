How the site moves: opening, wipes and handwriting

The site used to animate only when you scrolled. Now it opens with a drawing, changes pages with a wipe of paper tiles, writes its headings in by hand and answers every click. Here is how that works, what I decided and what it costs.

By Nate AndersonNov. 21, 20265 min read5 sourcesLab 5 of 7

01Why the site moves

The site is made of sketches, and a sketch has a before and after: lines appear, then fill in. Pages that just snap from one to the next throw that away. I wanted every moment of waiting (the first load, a reload, a link click) to be a small drawing instead of a blank flash, and I wanted headings to look written rather than printed.

The references pushed the same way. The tile collages, grid circles and squares from the reference sheets already work as flat, cut-out shapes, which makes them easy to move: a tile can grow, spin and shrink without any new art.

02What plays, and when

  1. The opening. On the first visit of a browser session, and on every reload, a sheet of paper tiles covers the page. The logo draws itself, “Redrawn Valley” writes in, a tagline fades up, and the tiles shrink away from the center. It never blocks clicks on the page underneath, and a tap skips ahead.
  2. The page wipe. Following a link covers the page with tiles that grow outward from where you clicked, with the name of the section you are going to written on them. The next page lifts the same tiles from the same spot, so the two pages feel like one move.
  3. Handwritten headings. The page title writes in letter by letter, each letter bouncing on the Wobble font’s bounce axis before it settles, with a pencil squiggle drawn under it. Section headings do the same as they scroll into view.1
  4. Small answers. A click or tap leaves a quick pencil burst. Links get a wavy underline that sweeps in. Buttons spring and squish. Rows slide and their icons tilt. Rules draw on, and figures get crop marks in their corners for a moment.

Back and forward buttons skip the opening and the wipe, because showing an animation on a page you are returning to feels slow.

03The decisions I made

Build the wipe myself instead of using the browser’s page transitions

The View Transition API can fade between pages with almost no code, but it is newer, so older browsers get nothing, and it only crossfades snapshots.2 A script that covers the page, remembers where you clicked, and lifts the cover on the next page works the same everywhere and can show tiles in our own colors.

CostEach navigation waits about 0.8 s before the next page starts to load, a delay the browser’s own transition would not add.

Paint a paper sheet before anything else

The script sits in the head and adds one CSS rule that paints paper over the page before the first frame, so there is no flash of unstyled content. A three second failsafe removes the sheet if anything goes wrong.

CostIt is a blocking script, though a small one, and it hides the page during the opening.

Hold the sheet in the top layer

The tiles live in a manual popover, which browsers draw above everything including open dialogs, so a link chosen from the search dialog is still covered.3 Browsers without popovers fall back to a very high z-index.

CostA top-layer sheet cannot be hidden by page code once it is open, so the failsafe has to remove it.

Animate tiles with the Web Animations API

Over a hundred tiles need staggered delays that depend on their distance from the click. Setting those per tile in code is simpler than generating CSS, and only transforms animate, so the browser can run them on the graphics card.4

CostOn a very slow phone a hundred animated tiles may drop frames. I have not measured that.

Turn everything off for reduced motion

Under the reduced-motion setting none of this runs: no opening, no wipe, no dab, and headings stay plain text. Large movement across the whole screen is the kind of motion that setting exists to avoid.5 Embed frames inside lab articles are off too, so a frame never covers its own article.

CostThose visitors never see the opening drawing.

04The live demo

Replay the opening, try the wipe from three starting points, write a heading again, click the grid for the pencil dab and change the speed. The effects play inside the frame, so they cover only the frame.

05What I could not verify

Limits of this lab

  • All timings (1.5 s, 0.5 s, 0.8 s) are my own settings, tuned by eye on a desktop and a phone-size window. I did not measure frame rate on real phones.
  • I tested in one Chromium build. Safari and Firefox should run it, since it uses long-standing APIs, but I have not seen it there.
  • Each letter of a heading is its own element, and I gave each heading an accessible label with its full text. I have not tried it with a screen reader.
