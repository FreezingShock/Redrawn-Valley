The sources library: every citation, found by script

Every claim on this site has a numbered note, but the notes live on two dozen separate pages. The library collects all of them in one searchable list, shows every page that cites each source and the sentence it backs, and jumps you to the exact spot.

By Nate AndersonNov. 21, 20265 min read3 sourcesLab 6 of 6

01What the library is for

Evidence is the point of this site, but a reader who wants to know “where did 121°F come from, and who else used that source?” has to open pages one by one. I wanted one place that answers three questions fast: what are all the sources, which pages lean on each one, and what exactly did I use it for.

02How it reads the pages

The site grew three citation styles: field guide entries use rds-fn markers and an rds-notes list, notes and lab articles use rv-fn and rv-sources, and the studies use plain superscript links to a numbered list. Rather than force one format, scripts/build_sources.py looks for the thing they share: a link to an in-page #id, inside a superscript or a footnote class, that points at a list item.2 The list item is the source; each link is one use.3

Sources are merged by web address with the scheme, www, tracking tags and trailing slash ignored, so the same article cited from three pages becomes one entry with three places of use. For each use the script keeps the sentence the marker closes, the section heading above it, and the marker’s order on the page. It also reads the label I put beside a source (“Government page”) and any caveat I wrote (“seen only as a search excerpt”). Pull quotes that cite as plain text, like “[3]”, count as quoted uses.

Types come from that label when it exists and otherwise from rules on the publisher’s address: a .gov address is Government, a known newsroom is News, and so on. Topics come from the words on the citing pages. Both are rules, not judgment, and I checked the output by reading the full list once and fixing the rules that put a state agency under “Other.”

03Jumping to the exact sentence

A link to a page is not enough when a page has eleven citations. Each use in the library links to page/#cite=note-lat.2, which means “the second marker on this page that points at #note-lat.” A small script on every page, assets/rds/cite-jump.js, finds that marker the same way the build script did, scrolls to it, pulses it, and highlights the sentence it closes. A bar at the bottom lets you step through the other uses of that source on the page, jump to its entry, or go back to the library.

The sentence is highlighted with the CSS Custom Highlight API, which styles a text range without wrapping it in new elements.1 It works in current Chrome, Edge, Safari and Firefox, and on older browsers the whole paragraph is tinted instead. Some pages hide a marker at small widths (the field guide’s at-a-glance box on a phone), so the script falls back to the next visible use and says which one it is showing.

04The decisions I made

Read the pages; never keep a separate list

A hand-kept bibliography goes stale the first time I forget it. The pages are the single source of truth, and the library is a view of them. A GitHub Action regenerates the file on every pull request, and the check script warns if it is stale.

CostA page that does not use numbered notes is invisible to the library, and two pull requests that both change the generated file can conflict.

Jump links carry an order, not a hand-placed anchor

Many markers have no id of their own, and adding one to each would mean editing every page and every future page. The order of a marker among those for the same source is enough to find it again.

CostIf I add a citation above an existing one and do not rebuild, an old link lands one use off. The rebuild fixes it; the old address does not know.

Search the claim, not only the title

People remember “the 121 degree record,” not “Wigglesworth and Cosgrove.” The search covers the sentence each source backs, the section and the citing page, and shows the best matching sentence under the result.

CostThe data file is about 115 KB, loaded once. That is fine for 99 sources and would need a smarter index at a few thousand.

Show caveats, and do not rate sources

If I wrote “I did not check its underlying data” beside a source, the library shows it and can filter to it. It does not score quality, because I would be inventing a number.

CostA source with no caveat is not thereby good; it only means I did not write one.

Rules for types and topics

Rules are predictable and easy to fix in one place. Asking a model or tagging by hand would be slower and would drift.

CostSome labels are wrong at the edges, such as a nonprofit report labeled as a report.

05The live library

Search a word, a number or a topic, filter by type, open a source to see every use, and press Jump to this claim. Press / to focus the search box.

06What I could not verify

Limits of this lab

  • I read the generated list once for wrong types and topics. I did not measure how often the rules are wrong.
  • The highlight is a visual cue only. The custom highlight does not carry meaning for screen readers,1 so the bar at the bottom says in text which source and which use you were sent to. I have not tested it with a screen reader.
  • I tested the jump links in one desktop and one phone-sized browser window, not on real phones or older browsers.
  • A page that was edited after someone saved a jump link can land one use off until the library is rebuilt.
