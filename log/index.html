How this log is made

It writes itself from git

A script reads the repository’s history and each page’s own title and description. One entry is one merged pull request. A pull request that adds a page lists it as New; one that edits a page lists it as Updated.

Automatic

scripts/build_log.py rebuilds this page, the feed and assets/log.json. A workflow reruns it after every merge to integration, so no one edits the log by hand.

In my words

Put a line starting Log: in a pull request description to set the summary, Log-Type: to pick the type, or Log: skip to leave it out. With none, the entry shows the commit subject.

Limits

Dates are commit dates, not publish dates. The first commits were bulk imports, so their file counts are large. I cannot see edits made outside git.

The feed address is /log/feed.xml. A machine-readable copy of the log, with a first-added and last-updated date for every page, is at /assets/log.json.
